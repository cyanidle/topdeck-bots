# collectbot — сканер коллекции MTG

Telegram-бот: пользователь присылает фото или видео карт — сообщением, кружком
или файлом — движок [`cards/`](../cards/) читает строку коллекционера, и
распознанные печати попадают в личную коллекцию в SQLite. Имена карт подтягивает Scryfall
(переиспользуется клиент из [`auctions/topbot`](../auctions/)).

## CRUD

| Операция | Как |
|---|---|
| **create** | прислать фото/видео — сообщением, кружком или файлом — каждая распознанная печать +1 копия; `/add TMT:67`, `/add Ninja Teen`, `/add TMT:67 3` |
| **read** | `/list` — по сетам, с количеством копий |
| **update** | кнопки `➖`/`➕` под одиночным результатом скана, `/sub TMT:67` (пачка карт — без кнопок, командами) |
| **delete** | кнопка `🗑` под одиночным результатом скана, `/del TMT:67` |

Каждый показ карты в видео и каждая карточка на фото — одна физическая копия
(стопку листают по карте за показ). Ошибся — `➖` под одиночным результатом скана,
в пачке — `/sub TMT:67`.

## Запуск

```bash
cp .env.example .env       # вписать BOT_TOKEN
./collection.sh            # venv берётся из ../auctions/.venv (COLLECTION_VENV для своего)
```

Тесты: `../auctions/.venv/bin/python -m unittest discover -s tests -t .` из папки
`collection/`. Данные: `data/collection.sqlite3` (в git не попадают).

## Логи

`LOG_LEVEL` (по умолчанию `INFO`), `LOG_FORMAT=json` и `LOG_FILE` — в `.env`; по умолчанию
текст в stdout. Под лог попадает всё, что нужно для разбора «почему не сработало»:

* приём медиа: тип, размер, `file_id`/`file_unique_id`, длительность и разрешение;
  отклонения (не тот формат, слишком большой);
* скан движка: кадры/OCR-прочтения, время и поимённый итог `SET:N[канал]` (кто через
  `codes`, кто `unknown`);
* Scryfall: батчи, найденные имена, ненайденные печати;
* каждая мутация коллекции (insert/update/delete с пользователем и идентичностью);
* команды, кнопки, необработанные сообщения, трейсбеки любых ошибок хендлеров.

## Как устроено

```
collectbot/
  config.py    — .env → Settings (общий load_env_file из topbot)
  db.py        — CollectDatabase(topbot.Database): таблицы collection_cards,
                 prints_cache поверх схемы topbot (users/card_names/sets/meta из коробки)
  scanner.py   — ctypes-биндинг cardscan: фото/видео → JSON-отчёт → ScanCard
  resolver.py  — печать «сет:номер» → имя карты: кэш prints_cache, потом Scryfall
                 /cards/collection (батчами ≤75), негативный кэш на 7 дней
  bot.py       — aiogram: команды, медиа-хендлеры, кнопки ±/🗑
```

Шаринг с соседями по репо — сознательно максимальный:

* **интерпретатор и пакеты** — `auctions/.venv` (aiogram, aiohttp уже там);
* **`topbot`** — `Database`/`ensure_user`, `ScryfallClient`, `Card`, `plural`,
  `setup_logging`, `load_env_file`;
* **`cardscan`** — ctypes-биндинг движка `cards/` (пути добавляются в
  `collectbot/__init__.py`, работает из любого cwd).

Пользовательские медиа — временные: файл скачивается в `TemporaryDirectory`
и удаляется сразу после скана, в базе остаются только идентичности.

## Ограничения (базовая версия)

* Распознавание — только OCR строки коллекционера (канал codes): C API движка
  не поддерживает pHash/ORB-индекс, поэтому 1.9 ГБ кэша эталонных картинок боту
  не нужны вовсе. Карта в блистере/с бликом честно уходит в `unknown`.
* Скан видео — минуты на длинный ролик (движок обрабатывает каждый кадр;
  `SCAN_STRIDE=2` в `.env` прореживает детектор на треть без потери качества — замер
  на эталонном 30-сек видео: 195с → 137с, те же карты);
* Имена карт — только из кэша/Scryfall; без сети бот показывает `SET:номер`.

## Дальше (свип оптимизации распознавания)

1. Персистентные ORB-дескрипторы в индексе вместо чтения эталонных jpg в
   рантайме (`HashIndex::verifyArt` делает `cv::imread`) — кэш изображений
   станет временным: скачал → захэшировал → выбросил.
2. Опция `phash_index` в C API — канал картинки для бота.
3. `stride`/`ocr_stride` для длинных видео и профилирование горячего цикла.
