# Идентификация карт по базе Scryfall и индексу pHash

Дополнение к `spec-detector.md`: строка коллекционера на 720p имеет высоту 10–18 px и
читается нестабильно, поэтому основным источником идентичности становится **картинка
карты**, а OCR — уточняющим (тираж, язык, редкость) и резервным каналом.

## Данные

`cards/tools/scryfall_fetch.py` скачивает в локальный кеш `cards/data/scryfall/`
(в `.gitignore`, не коммитится):

* `meta.jsonl` — `{set, collector, name, id, path}` по одному на печать;
* `images/<set>_<collector>.jpg` — `image_uris.small` (146×204) из Scryfall.

Скачивание последовательное (curl, пауза `--delay`, по умолчанию 0.08 c — заметно ниже
лимита Scryfall в 10 запросов/с), с докачкой: уже известные `id` пропускаются, поэтому
прерванный прогон продолжается с того же места.

```bash
python3 cards/tools/scryfall_fetch.py --sets dds,fin,war,akh,hob,tmt,msh,c18 \
        --out cards/data/scryfall
```

## Индекс

```bash
cards/build/cardscan --build-index cards/data/scryfall/meta.jsonl cards/data/scryfall/phash.tsv
```

Строка индекса: `set \t collector \t name \t pHash(вся карта) \t pHash(арт) \t path`.

* `pHash` считается `cv::img_hash::pHash` (64 бита, hex).
* Хэш арта — по области `x 10–90 %`, `y 11–66 %` (рамка у карт одного сета почти
  одинаковая и только мешает), это главный ключ поиска.
* Хэши инвариантны к масштабу, поэтому кроп 630×880 с камеры сравнивается с картинкой
  146×204 напрямую.

## Поиск

```bash
cards/build/cardscan --lookup cards/data/scryfall/phash.tsv /tmp/crop.jpg
cards/build/cardscan ~/Documents/cards.jpg --phash-index cards/data/scryfall/phash.tsv
```

Ранжирование — по расстоянию Хэмминга хэша арта (полный хэш — тайбрейкер). Результат
принимается, если

* `artDistance <= indexMaxDistance` (по умолчанию 26), и
* лучший вариант отрывается от второго не меньше чем на `indexMinMargin` (2 бита).

Для видео голосование по сегменту: каждый `ReadSample` даёт свой lookup, принимаются
совпадающие `SET:number`, нужно `indexMinSupport` (2) голоса. Идентичность из индекса
перебивает OCR-коды (картинка информативнее строки на 13 px), согласие с OCR повышает
`confidence` и помечается в отчёте как `identified_by: "index"`.

## Замер (пилот, 2026-11-21)

Индекс из 64 карт DDS, запрос — фото `~/Documents/cards.jpg`:

```
 1. art=19 full=15  DDS 51  Sylvan Might     <- верно (OCR: DDS 051/065 C)
 2. art=22 full=21  DDS 61  Mountain
```

Отрыв 3 бита, ответ №1 верный — при том что OCR на том же фото даёт `DDS 051/065`; оба
канала согласны, то есть индекс годится и для проверки OCR.

## Ограничения

* Кеш и индекс — локальные данные: их размер растёт линейно (≈14 КБ на печать);
  полная база Scryfall (~110 тыс. печатей) — это ~1.5 ГБ картинок и часы скачивания,
  зато разово.
* Одну и ту же картинку имеют несколько печатей (переиздания, промо): индекс вернёт
  самую близкую по хэшу, а точную печать (сет/номер/тираж) уточняет OCR и, если нужно,
  отдельный запрос в Scryfall по `set+collector`, как делает бот.
* Хэш чувствителен к сильному блеску/перекрытию арта пальцем — при плохом отрыве
  (margin) результат отбрасывается, карта остаётся `unknown`.
