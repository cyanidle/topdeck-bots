# Идентификация карт по базе Scryfall и индексу картинок

Дополнение к `spec-detector.md`: строка коллекционера на 720p имеет высоту 10–18 px и
читается нестабильно, поэтому второй источник идентичности — **картинка карты**.
Картинка не заменяет OCR, а подтверждает его и заполняет пробелы: строка коллекционера
даёт точную печать, картинка — карту, когда номер не читается.

## Данные

`cards/tools/scryfall_fetch.py` скачивает в локальный кеш `cards/data/scryfall/`
(в `.gitignore`, не коммитится):

* `meta.jsonl` — `{size, set, collector, name, id, path}` по строке на печать;
* `images/<set>_<collector>.jpg` — картинка Scryfall выбранного размера.

Размер по умолчанию — `normal` (488×680, ~100 КБ). `small` (146×204) годится только для
грубого pHash: на 117×112 пикселях арта keypoint-матчинг не находит достаточно признаков
(см. «Проверка картинки»). `normal` — 4 МБ на 40 карт, полная база ~110 тыс. печатей — это
~10 ГБ, поэтому кеш пополняется по сетам.

```bash
python3 cards/tools/scryfall_fetch.py --sets dds,fin,war --size normal \
        --proxy socks5h://127.0.0.1:1080
```

Скачивание идёт последовательно (curl, пауза `--delay`, по умолчанию 0.08 c — ниже лимита
Scryfall в 10 запросов/с), с докачкой: известные `id:size` пропускаются, поэтому прерванный
прогон продолжается с того же места. `--force` перекачивает уже известные картинки
(например, после смены `--size`).

### Зачем прокси

В этой сети большие ответы CDN обрываются: `curl` получает HTTP 200, `content-length:
99601`, и замирает после ~3.5 КБ (то же и с `Range`, и с HTTP/1.1). Картинка `small`
(~14 КБ) успевает доехать, `normal` — нет. Поэтому загрузка идёт через xray-туннель
(`--proxy socks5h://127.0.0.1:1080`), в конфиге которого `domain:scryfall.io` и
`domain:scryfall.com` маршрутизируются в proxy-outbound.

Обрезанный JPEG открывается почти любым декодером и даёт мусорный хеш, поэтому
`curl_file` проверяет маркер конца файла `FF D9`, а не только размер: битые загрузки
повторяются, а сет не считается скачанным, пока не скачались все его картинки.

## Индекс

Индексом владеет `cards/tools/scryfall_index.py` — он же индексатор, он же экспортёр:

```bash
# один проход: импорт кеша, хеширование нового, сверка размеров сетов, экспорт TSV
python3 cards/tools/scryfall_index.py --sets dds,fin --size normal \
        --proxy socks5h://127.0.0.1:1080

# долгоживущий индексатор: бот читает индекс, пока он обновляется
python3 cards/tools/scryfall_index.py --watch --size normal --force \
        --proxy socks5h://127.0.0.1:1080 --fetch-limit 1 \
        --sets dds,fin,war,akh,hob,tmt,msh,c18,...
```

Состояние — SQLite `cards/data/scryfall/index.db` (WAL):

* `prints` — `key(id:size)`, `set_code`, `collector`, `name`, `path`, `full_hash`,
  `art_hash`, `hashed_mtime`, `hashed_bytes`;
* `sets` — `code`, `expected` (сколько печатей у Scryfall), `checked_at`, `fetched_at`,
  `size` (каким размером сет скачан целиком);
* `state` — `export_needed`, `exported_at`.

Правила совместной работы с ботом:

* **Экспорт атомарный.** Индексатор пишет `phash.tsv.tmp-<pid>` и делает `rename` поверх
  старого файла: движок видит либо прежний, либо новый полный индекс, но не половину.
* **Писатель один.** Транзакции короткие (`BEGIN IMMEDIATE`, батч 300–500 картинок),
  `busy_timeout` 30 c; читатели SQLite (если бот захочет ходить в базу напрямую) не
  блокируются подолгу и не видят полубатч.
* **Хеширует движок.** `cardscan --hash-manifest <in.txt> <out.tsv>` считает те же
  `pHash`, что и поиск, поэтому индекс и запрос бит-в-бит совместимы (проверено: 2613
  общих записей старого индекса и нового экспорта — 0 расхождений).
* **Сверка количества.** Раз в `--reconcile-interval` индексатор спрашивает у Scryfall
  `total_cards` по каждому известному сету и, если в базе меньше, докачивает сет.
  Именно поэтому индекс «не стареет»: новый выпуск сета доезжает сам.

Строка индекса (TSV, 6 колонок):
`set \t collector \t name \t pHash(вся карта) \t pHash(арт) \t путь к картинке`.

* `pHash` — `cv::img_hash::pHash` (64 бита, hex), считается с **квада детектора**, а не с
  расширенного кропа: кроп добавляет стол под строкой коллекционера и сдвигает арт
  внутри кадра, из-за чего хеш перестаёт совпадать с эталоном.
* Хэш арта — по области `x 10–90 %`, `y 11–66 %`.

## Поиск и проверка картинки

```bash
cards/build/cardscan --lookup cards/data/scryfall/phash.tsv /tmp/crop.jpg
```

`--lookup` печатает для первых десяти кандидатов `art`/`full` (расстояния Хэмминга),
`inliers` и `good` (результат keypoint-проверки). Движок принимает карту по той же схеме:

1. **pHash — грубый фильтр.** Кандидат проходит, если `artDistance <= indexMaxDistance`
   (16), `fullDistance <= indexMaxFullDistance` (22) и отрыв от второго кандидата
   `>= indexMinMargin` (3).
2. **ORB — решение.** `HashIndex::verifyArt` берёт ORB-признаки арта кадра и эталонной
   картинки, ratio-тест 0.78 и RANSAC-гомографию; карта принимается при
   `inliers >= indexMinInliers` (12).

Почему так, а не по одному pHash: одна и та же карта, снятая под углом, отличается от
своего эталона на ~18 бит, а посторонняя карта — на 17–20 бит, то есть **pHash не
различает** их (на фото `cards.jpg` настоящая `DDS:51` стоит на 2-м месте с `art=18`,
первое место занимает случайная `FIN:421` с `art=17`). ORB на тех же кадрах разделяет
уверенно: `DDS:51` — 76 inliers, `TMT:67` — 5; на кадре с «Ninja Teen» — 19–29 inliers
против 5–8 у чужой карты. Поэтому pHash только сужает круг, а идентичность даёт
проверка.

Для видео проверка выполняется один раз на кадр (в `analyzeVideo`, где есть кроп), а
`buildCardsFromReads` голосует уже по проверенным идентичностям (`ReadSample::indexIdentity`).
Нужно `indexMinSupport` (2) голоса на сегмент.

## Совместная оценка (fusion)

Три канала, веса: `codes` 1.6, `index` 1.2, `name` 0.8. Строка коллекционера сильнее
картинки, потому что её номер принимается только после голосования (`minNumberSupport`
2, согласие 25 %); картинка подтверждает (`identified_by: "codes+index"`) или заполняет
пробел, когда номер не прочитан (`identified_by: "index"`). Согласие каналов поднимает
`confidence`.

## Замеры (2026-11-22, этот хост)

| вход | результат |

## Ограничения

* Кеш и индекс — локальные данные (`cards/data/scryfall/`, ~100 КБ на печать в `normal`).
  Полная база (~110 тыс. печатей) — ~10 ГБ и часы загрузки через туннель.
* Одна картинка у нескольких печатей (переиздания, промо): индекс вернёт самую близкую,
  точную печать уточняет OCR, а если номер не читается — остаётся `set` + номер печати,
  которую нашла картинка.
* Карта в цветной прозрачной обложке (зелёный свет на клипе с `TMT:198`) не совпадает ни
  по pHash, ни по ORB: такой кадр остаётся нераспознанным, и это правильно — лучше
  «unknown», чем чужая карта.
* Для `--reads` (реплей сохранённого таймлайна) индексный канал выключен: в файле нет
  ни кропов, ни проверки.
