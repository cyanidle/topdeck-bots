# План реализации

Принцип: каждый этап заканчивается **проверяемым результатом** (команда/URL, который можно показать).

```
┌── Этап 0 ─ ✔ ──────────┐   ┌── Этап 1 ─ ✔ ──────────┐   ┌── Этап 2 ─ ✔ ──────────┐
│ Каркас + клиент TOPDeck│──►│ Watchlist (БД + aiogram)│──►│ Поллер аукционов       │
│ tools/topdeck_probe.py │   │ /add /list /remove      │   │ 60 с, окна 1д/1ч/15м/5м │
└────────────────────────┘   └──────────────────────────┘   └────────────────────────┘
```

Объём продукта — бот с watchlist'ом и уведомлениями об аукционах (плюс цены по запросу).
Цены-снимки, история продаж, веб-UI и деплой на сервер — **вне скоупа** (см. `spec-product.md` §9).

## Этап 0. Каркас репозитория и клиент TOPDeck — ✔ сделано

* `pyproject.toml` (Python 3.10+, `aiogram`, `fastapi`, `uvicorn`, `aiohttp`, `jinja2`).
* Пакет `topbot/`: `config.py`, `db.py` (миграции), `clients/topdeck.py`, `clients/scryfall.py`, `models.py`.
* `clients/topdeck.py`: fetch+gzip, `embedded_records`, `search_singles` с проверкой усечения 1478, `fetch_auctions`, `fetch_lot` (состав), `finished_search`.
* Тесты: разбор сохранённых HTML-фикстур (аукционы, поиск, страница лота) — без сети.
* **Проверка:** `python -m topbot.cli search "Lightning Bolt"` печатает предложения.

## Этап 1. Бот и watchlist (без поллера) — ✔ сделано

* aiogram 3.x, `.env`-конфиг, `Bot(AiohttpSession(proxy=…))`, команды `/start /menu /add /list /remove /price /status /settings /mute /help /admin`.
* Нормализация имён: Scryfall `named?fuzzy` + локальный каталог `card_names` (35 557 имён), дизамбигуация инлайн-кнопками.
* БД (SQLite WAL) по `spec-data-model.md`, миграции идемпотентные.
* **Проверка:** в Telegram добавляются карты, `/list` показывает их, `/price` отдаёт минимальные предложения.

## Этап 2. Поллер аукционов и уведомления — ✔ сделано

* `AuctionPoller` (60 с, один запрос на цикл; состав лота — раз в 10 минут), парсинг, `upsert` лотов, матчинг `lot → card` по названию (точное/префикс/нечёткое) и по составу лота, кэш `lot_cards` с версией правил (`meta.match_version`).
* `Notifier`: окна 86400/3600/900/300 (окно «3 часа» упразднено 2026-11-17, см. `RETIRED_WINDOWS` в `config.py`), дедуп по `UNIQUE(user, kind, ref, window)`, лимит 20/час, пауза `/mute`.
* `AdminAlerter`: 5 неудачных опросов подряд, 3 опроса с 0 лотов или 2 усечённых опроса → сообщение админу (не чаще раза в час), восстановление — отдельным сообщением.
* Сообщение с лотом: заголовок, ставка, цены продавцов, продавец+отзывы, фактический остаток, кнопка «🚫 Не интересно» (игнор лота пользователем).
* **Проверка:** уведомление приходит в нужное окно (`data/logs/bot.jsonl`: `auction notification`), повторных нет; `curl 127.0.0.1:8080/healthz` отдаёт `status=ok`.

## Открытые вопросы (не блокируют)

* Анти-снайп-продление на TOPDeck: сдвигается ли `date_estimated` после ставки в последние минуты — проверить вручную на живом лоте (research §11.1). Если да, окна считаются от свежего `end_ts`, что уже так и работает.
* Цикл поллера возвращается к ~3 с, когда очередь составов (`lots_needing_composition`) исчерпана; пока очередь не пуста — цикл ~65 с при бюджете 40 страниц.

## Риски и как закрываем

| Риск | Что делаем |
|---|---|
| Продление аукциона меняет конец | `end_ts` обновляем каждый опрос; окна считаем от свежего значения |
| Сайт изменит вёрстку/встроенный JSON | алерт админу после двух опросов подряд с `0` лотов |
| Telegram недоступен | Xray в процессе, `data/logs/bot.jsonl` + `degraded` в `/healthz`, автоперегенерация конфига из подписки |
| Бан по IP за агрессивность | свой User-Agent, пауза ≥1.5 с перед запросом, 1 запрос аукционов в минуту (страницы лотов — раз в 10 минут), никаких попыток в закрытый `/api/` |
