# Спецификация продукта: TOPDeck watchlist-бот

Статус: черновик (2026-11-15). Источник данных — [`research-topdeck-api.md`](research-topdeck-api.md).

## 1. Что делаем

Telegram-бот, который следит за **watchlist'ом карт каждого пользователя** и присылает уведомления:

1. **Аукционы TOPDeck**, заканчивающиеся через **1 день / 3 часа / 1 час / 15 минут** — если лот содержит карту из watchlist'а пользователя.
2. По запросу — **минимальные предложения продавцов и магазинов** по карте (команда `/price` и ссылка «цены» в `/list`), чтобы сравнить с текущей ставкой на аукционе.

Единственный поллер обслуживает всех пользователей одновременно.

## 2. Роли и сущности

```
Пользователь (tg_id, username, tz, настройки)
   └── Watchlist: карта + флаги окон уведомлений
Карта (canonical: scryfall_id | oracle_id, name_en, name_ru, set, collector_number, image)
Лот аукциона (topdeck lot_id, title, end_ts, current_bid, bin, seller)
Предложение (offer): карта + источник + цена + кол-во + продавец + ссылка + stamp + текст продавца (`line`: сет, номер, язык, состояние)
Событие уведомления (dedupe key: user_id + kind + lot_id + window)
```

## 3. Карточки карт: нормализация через Scryfall

Scryfall — **вспомогательный** сервис (конфигурируемый, можно выключить: `SCRYFALL_ENABLED=1`, `SCRYFALL_BASE=https://api.scryfall.com`). Трафик к Scryfall идёт **через VPN** (правило в Xray: `domain:scryfall.com`, `domain:scryfall.io`), потому что из РФ он нестабилен.

Соблюдаем требования Scryfall API:

* **User-Agent** — точный, наш: `topbot/<version> (+contact)`; никаких библиотечных UA.
* **Accept** — обязателен: `application/json;q=0.9,*/*;q=0.8`.
* **Rate limit**: не чаще 10 запросов/с на эндпоинт → в клиенте глобальный троттл `min_interval_s = 0.1` под `asyncio.Lock`, `429` → пауза по `Retry-After` (до 30 с) и до 2 ретраев, `5xx` → 2 ретрая с backoff.
* **Кеш**: результат `named?fuzzy`/`search` кладём в `cards` навсегда, «не найдено» — TTL 30 дней; массовые запросы — только `/cards/collection` (максимум 75 идентификаторов).
* **Лицензия/данные**: не проксируем и не перепаковываем данные Scryfall (карточки храним в БД, наружу API не ретранслируем), не требуем оплату за доступ, не используем логотипы/имя Scryfall как эндорсмент. Для изображений: не обрезаем копирайт/художника (используем `image_uris.small/normal` целиком), для `art_crop` — указываем художника из поля `artist`.
* Ошибки/лимиты — не роняют бота: при недоступности Scryfall работаем по локальному словарю имён (`cards` + RU-словарь из TOPDeck).

* Ввод пользователя → `GET /cards/named?fuzzy=<q>`; если 404 → `GET /cards/search?q=<q>` (первые 5 кандидатов) → инлайн-кнопки выбора.
* Принимаем строки вида `4 Lightning Bolt`, `Lightning Bolt (2XM)`, `Удар Молнии` (RU: сначала локальный RU-словарь из TOPDeck, затем Scryfall `printed_name`/`name`).
* Храним `oracle_id` (идентичность карты) + `scryfall_id` последнего выбранного принта. Принт (сет/номер) важен для цены, но не для «какая это карта».
* Кэш ответов Scryfall в БД навсегда + TTL на «не найдено» (30 дней). Между запросами к Scryfall ≥100 мс, батчим через `/cards/collection` (до 75 идентификаторов за запрос) — это единственный массовый эндпоинт, который нам нужен регулярно.
* Scryfall недоступен → бот продолжает работать по локальному словарю имён (watchlist не ломается, только не будет авто-картинок/принтов).

## 4. Матчинг «лот ↔ карта»

Лот приходит строкой (`lot`), примеры форматов — в research §9.2. Пайплайн:

1. Нормализация: unescape HTML, `ё→е`, убрать `4x/1x` префикс, заменить `№`,`#`, снять `Foil/Borderless/Extended Art/Surge Foil/…` в флаги, выделить `(Сет, КОД, язык, номер)`.
2. Кандидаты имён: часть до `-`/`•`/`|` (RU) и после (EN); варианты без подзаголовка после `(`.
3. Сопоставление: точное совпадение с `cards.name_en` (lower) → иначе `name_ru` → иначе **префикс** → иначе токенное сходство (Jaro-Winkler ≥0.92) → иначе отбрасываем.
   * **Префикс** (`prefix_en`/`prefix_ru`): название начинается с имени карты (имя ≥6 символов), а остаток похож на метаданные — содержит цифру (сет/номер) или начинается с флага (`foil`, `nm`, `ru`, …). Так ловятся заголовки вида `Exploration 2XM #167`, `Mystic Remora Ice Age #87 EN NM-`, `Delighted Halfling LTR #158`: `SequenceMatcher` по ним даёт 0.60–0.82, то есть ниже порога 0.92, и без префикса лот не матчится по названию. Confidence 0.95, ниже точного совпадения. Продолжение имени словом (`Island Sanctuary` при карте `Island`) префиксом не считается; если на один и тот же кандидат претендуют несколько карт, побеждает самое длинное имя (разные части заголовка, разрезанные `-`/`•`/`|`, по-прежнему могут дать разные карты).
4. **Мультикарточные лоты** («Полноформатные Тропы KHM», «Лот Ультиматумов (список внутри)») по названию не матчатся. Для них (и для лотов, чьё название ни с чем не совпало) поллер один раз скачивает страницу лота `/apps/toptrade/auctions/<id>` и берёт **состав лота** из блока «Описание» (`div.tt-item-desc`): имена карт — это ссылки `<a class="topdeck_tooltipCard">` (в т.ч. по две в строке через `//`, например `Blightstep Pathway // Searstep Pathway`), а если ссылки нет — текст строки до скобок (`Bonder's Enclave (IKO,#363, Showcase)`). Каждое имя матчится тем же пайплайном, метод помечается `composition:*`.
5. Результат матчинга кэшируем по `lot_id`: `title_hash` (заголовок) + `composition_ts` (состав скачан один раз; при появлении состава кэш инвалидируется).

Матчинг исполняется в поллере по уже скачанному списку — O(357 лотов × токены) раз в 14 минут, дёшево.

Уведомление по мультилоту: если карта найдена по составу, в тексте есть строка «Из вашего списка в лоте: <имя>» — чтобы было понятно, за что именно лот в списке. Один лот = одно уведомление на окно, даже если внутри несколько карт из watchlist.

## 4.1 Подсказки при вводе (автокомплит)

Ввод карты не требует точного имени:

* Локальный каталог `card_names` (35 549 имён из Scryfall `/catalog/card-names`, синк раз в 7 дней, в одной транзакции) → мгновенный офлайн-поиск: точное совпадение → **сразу добавляем**; иначе — **топ-5** кандидатов инлайн-кнопками (ранжирование: точное → префикс → начало слова → подстрока).
* `/add` без аргументов → бот переходит в режим ожидания запроса: любое следующее сообщение трактуется как поиск (команды не перехватываются).
* Русский ввод — **через Scryfall**: `search?q=<префикс>*&include_multilingual=true` (wildcard по локализованным именам) и `named?fuzzy` (понимает RU); `autocomplete` локализованные имена не индексирует. Каждый найденный результат пополняет локальный RU-словарь (`printed_name`).
* Если карта добавлена по английскому имени и у выбранного принта нет `printed_name`, бот один раз спрашивает `GET /cards/search?q=!"<имя>" lang:ru&include_multilingual=true` и сохраняет русское имя (`ScryfallClient.localized_name`). При старте так же догоняются все карты watchlist'а без `name_ru` (`CardCatalog.fill_russian_names`), после чего кэш матчинга инвалидируется — иначе лоты с русскими названиями (`Капитан Лесничих Эоса РУС MH1 #254`) остаются без совпадения. Карты, у которых русского принта нет вообще, запоминаются в `meta.cards_without_ru`, чтобы не спрашивать Scryfall на каждом старте.
* Опечатки в латинице: `autocomplete` → если пусто, `named?fuzzy` (`tarmogoyff` → Tarmogoyf).
* TOPDeck `singles/search` — только последний фолбэк, если Scryfall ничего не дал: в `name` приходит реальная карта из строки продавца (её и берём в подсказки), а `eng_name`/`rus_name` — канонизированный запрос.
* Несколько названий в одном сообщении (`/add Lightning Bolt, Snapcaster Mage`) — обрабатываются по очереди; спорные имена складываются в очередь и предлагаются кнопками по одному.
* Если Scryfall недоступен — работает локальный каталог, `/add` не ломается.

## 5. Команды бота (aiogram 3.x)

| Команда | Поведение |
|---|---|
| `/start` | регистрация, краткая инструкция |
| `/menu` | заново прислать reply-клавиатуру главного меню |
| `/add <текст>` | многострочный ввод, батч-добавление, дизамбигуация кнопками |
| `/remove <карта>` | удалить по части названия; в `/list` у каждой карты есть ссылка «удалить» |
| `/list` | одно сообщение с HTML-разметкой, без inline-кнопок; каждая карта — отдельный блок через пустую строку: жирная ссылка на ближайший аукцион, строка про лоты (`3 лота · от 500 ₽ · ближайший через 1 д 2 ч`), строка `💰 Цены у продавцов: 1 200 ₽ Umezawa · …` (до 3 самых дешёвых, **из кэша БД**, который обновляет `PricePoller` раз в 15 минут) и строка действий `› цены · удалить` (deep-link `t.me/<бот>?start=price_<id>` / `?start=rm_<id>`, обрабатывается в `/start`, служебное сообщение `/start` бот удаляет). Если карты в кэше ещё нет (только что добавлена), бот один раз сходит в `singles/search` за ней; в заголовке — `💰 Прайсы из кэша: N назад` |
| `/price <карта>` | минимальные предложения по продавцам (свежесть `stamp`), **из кэша** — тот же, что наполняет `PricePoller`; в каждой строке — цена, кол-во, продавец и доступные детали из текста продавца: сет, номер, язык, состояние (`(SP, isd-78)`, `(UMA) #71`, `[EN] ISD (РЕЗЕРВ)`). Для карты вне каталога (нет в `cards`) — живой запрос `singles/search`: если карта нашлась точным совпадением `name`, показываются её предложения; если ответ нечёткий и смешал карты — вместо чужих цен бот присылает до 5 кандидатов с минимальными ценами («Точного совпадения по «Eladamri» нет — возможно, вы имели в виду: …») и просит уточнить запрос |
| `/settings` | окна уведомлений (1д/3ч/1ч/15м — вкл/выкл по клику). Тихих часов в боте нет: если ночью уведомления не нужны — пауза `/mute 8h` или настройка уведомлений на стороне клиента Telegram (Android/iOS умеют расписание «Не беспокоить»). Смена TZ/языка через бота недоступна |
| `/mute <1h|8h|off>` | пауза уведомлений |
| `/status` | **только админ** (в списке команд бота не публикуется): последний сбор лотов и цен, лаг, ошибки |

Кнопки: `➕ Добавить`, `📋 Список`, `⚙️ Настройки` — главное меню (кнопки «ℹ️ Статус» нет: статус — админская команда `/status`). Отдельной команды «аукционы» нет: лоты и ссылки на них живут в `/list`; отдельной кнопки «цена» тоже нет — цены открываются ссылкой «цены» в `/list` или командой `/price <карта>`. Inline-клавиатур в `/list` нет: действия живут в тексте (имя-ссылка, строка про лоты, строка цен при наличии предложений и «› цены · удалить»), поэтому под сообщением не остаётся блока из 16 кнопок; Telegram рендерит `<a href>`/`<b>` при `parse_mode=HTML`.

`/start` объясняет цель бота простыми словами: бот хранит список карт и присылает уведомления об аукционах на них.

Reply-клавиатуру клиент Telegram скрывает, пока пользователь печатает текст (поведение клиента, `is_persistent` его не отменяет), поэтому бот подкладывает её в каждое своё сообщение **без явного `reply_markup`** (сообщения с inline-кнопками — настройки, подсказки — меню не несут: Telegram не позволяет совместить два вида клавиатур), а команда `/menu` присылает её отдельно.

## 6. Уведомления

Окна по умолчанию: **24 ч, 3 ч, 1 ч, 15 мин** до `date_estimated` (можно отключать по пользователю).

Формат:

```
⏰ 15 минут до конца
Bayou — Reserved List (3ED, EN, №283)
Текущая ставка: 1 488 ₽ · 5 ставок
💰 Цены у продавцов: 700 ₽ Bernard · 800 ₽ Cornelius · 1 100 ₽ Alphonse
Продавец: Red_clix (Краснодар, 93 отз.)
[Открыть лот] [Скрыть карту]
```

Строка цен — та же, что в `/list`: до 3 самых дешёвых предложений **из кэша** (`card_offers`, его обновляет `PricePoller` раз в 15 минут), по одному (самому дешёвому) на продавца, ник обрезается до 18 символов. Показываются цены той карты, из-за которой лот попал в уведомление; если в кэше предложений нет — строки нет. Живых запросов при рассылке не делается.

Правила: не более одного уведомления на `(user, lot, window)`; глобальный предохранитель — 20 уведомлений/час на пользователя (дальше — сводка одним сообщением). Время суток бот не учитывает: тихих часов нет, ночная тишина — дело клиента Telegram или паузы `/mute`.

Точность: окна срабатывают **минута в минуту** — `WindowScheduler` просыпается ровно в момент `end_ts - окно` (тик ≤ 60 с нужен только чтобы подхватить новые лоты и повторить отложенные), поэтому 1д/3ч/1ч/15м приходят в номинал, а не «когда случился опрос». После простоя окно досылается, если осталось не меньше половины окна.

## 7. What we do NOT do (границы)

* Не делаем ставки и не логинимся в TOPDeck (только публичные гостевые страницы).
* Не парсим личные сообщения/профили, не собираем ПДн победителей сверх публичной таблицы.
* Точность ограничена: в штатном режиме окно приходит в номинал (±1 с), но после простоя процесса уведомление может прийти позже, а если осталось меньше половины окна — не прийти вовсе.

## 8. Нефункциональные требования

* Python 3.12+, aiogram 3.x, SQLite (WAL) локально.
* Один процесс `topbot` = aiogram + поллер (asyncio task) + мини-сервер (uvicorn) на `127.0.0.1:8080` с `/healthz`.
* Все внешние вызовы — через общий `aiohttp`-сессию с таймаутами, retry/backoff, троттлингом.
* Логи — структурированные (JSON) в файл `data/logs/bot.jsonl`.
* Метрики — `/healthz` (статус последнего опроса, число активных лотов) и счётчики поллера в БД (`poll_runs`).

## 9. Вне скоупа

Решением от 2026-11-16 не делаем: суточный `OfferPoller` со снимками цен и уведомлениями `price_drop`, историю завершённых лотов, полноценный веб-UI и деплой на сервер (systemd, `/readyz`, TLS). Спека веб-UI и соответствующие разделы плана удалены; `offers_snapshot`, `card_price_stats` и `watchlist.price_threshold` вычищены из схемы. Цены при этом доступны по запросу — `/price` и ссылка «цены» в `/list` читают кэш `card_offers`, который раз в 15 минут наполняет `PricePoller` по объединению карт из всех watchlist'ов; снимков истории и уведомлений о снижении цены нет.
