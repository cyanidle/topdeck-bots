# TOPDeck.ru — исследование публичных эндпоинтов (для бота слежения за картами и аукционами)

Дата сбора данных: **2026-11-15** (все ответы сняты живыми запросами, гость без авторизации).
Скрипт-репродукция: [`tools/topdeck_probe.py`](../tools/topdeck_probe.py).

## 1. TL;DR — что реально доступно без авторизации

| Что нужно боту | Источник | Формат |
|---|---|---|
| Предложения карт по продавцам и магазинам РФ (цены, количество, продавец, город, ссылка) | `GET /apps/toptrade/singles/search?q=<имена>` | HTML + встроенный JSON-массив |
| Все активные аукционы с абсолютным временем окончания | `GET /apps/toptrade/auctions` | HTML + встроенный JSON-массив (все лоты сразу) |
| История завершённых аукционов (цена, победитель, дата) | `GET /apps/toptrade/auctions/search?q=<имя>`, `/auctions/search/<page>?q=` | HTML-таблица, 30 строк/страница |
| Лента завершённых лотов «всё подряд» | `GET /apps/toptrade/auctions/finished/<page>` | HTML-таблица, 50 строк/страница, ~10 750 страниц |
| Карточка лота | `GET /apps/toptrade/auctions/<id>` | HTML |
| Профиль продавца, его витрина/аукционы/отзывы | `GET /apps/toptrade/member/<id>[/store|/aucs|/bids|/refs]` | HTML-таблицы |
| Топ трейдеров и поиск трейдера | `GET /apps/toptrade/refs`, `GET /apps/toptrade/refs/<page>`, поиск — `POST /apps/toptrade/refs/search` | HTML-таблица |
| Магазин (запечатанное, аксессуары, коллекции) | `GET /apps/toptrade/store`, `/store/category/<slug>/`, `/store/items/<id>`, `/store/pricelist`, `/store/search?q=` | HTML |
| Новостная RSS-лента (дайджесты, 30 записей) | `GET /apps/mainrss` | RSS 2.0 |
| Форумы IPS (темы, разделы, гостевой поиск) | `GET /forums/topic/<id>-<slug>/`, `/forums/forum/<id>-<slug>/?page=N`, `GET /search/?q=&quick=1` | HTML |

**Нет публичного JSON/GraphQL/REST для торговли.** Штатный Invision Community REST (`/api/`) и GraphQL (`/api/graphql/`) живы, но требуют API-ключ, который выдаёт только администрация. Все данные торговой площадки приходят **внутри HTML** в виде `JSON.parse("…")` — это и есть де-факто API.

## 2. Архитектура сайта

* Фронт — **nginx** (HTTP/2) + приложение **Invision Community** (IPS 4) на `PHP`; статика и часть редиректов отдаёт **Apache/2.4.41** (видно по `301` на `http://topdeck.ru/api/graphql/`).
* Кастомные приложения живут под `/apps/`:
  * `/apps/toptrade/` — синглы, магазин, аукционы, отзывы;
  * `/apps/cards/<Имя карты>` — прокси картинки карты (отдаёт `image/webp`, данных нет);
  * `/apps/mainrss` — RSS новостей;
  * `/apps/unlimited` — статьи (IPS Pages).
* Авторизация — cookie IPS (`ips4_IPSSessionFront`) + отдельная сессия приложения (`td_toprade_session`, TTL 1 час). Гостю доступны все перечисленные выше разделы на чтение.
* Внутренние AJAX-вызовы приложения требуют CSRF-пары, которая вшивается в каждую страницу:
  `ttAjax.init("/apps/toptrade/", "csrf_name", "csrf_value", "csrf<hash>", "<token>")`, поля уходят в теле запроса как `csrf<name>/csrf<value>` (см. `ToptradeAjaxHelper` в `/apps/toptrade/toptrade.es6.js`).
* robots.txt: закрыт только `/calendar/`; `meta-externalagent`, `meta-webindexer`, `bingbot` — запрещены целиком. Наш бот должен представляться своим User-Agent.

## 3. Ключевой эндпоинт: поиск синглов (цены)

```
GET https://topdeck.ru/apps/toptrade/singles/search?q=<urlencoded>
```

`q` — текст в `textarea`, поэтому допускает **несколько строк** = несколько карт за один запрос (проверено).
Параметров, кроме `q`, сервер не понимает (`page`, `format=json`, фильтры игнорируются).

Результат — HTML, внутри один блок:

```js
new SinglesSearchVM(JSON.parse("\u005B\u007B…"), …)
```

После раскодирования (`json.loads(json.loads('"…"'))`) получаем массив записей:

```json
{
  "source": "topdeck",
  "stamp": "2026-11-15 04:32:52",
  "qty": 2,
  "url": "https://topdeck.ru/forums/topic/442180/",
  "line": "\t2\u00a0\u00a0 Tarmogoyf Nest\u00a0\u00a0\u00a0 EXT ART M3C\u00a0\u00a0\u00a0 ENG, NM\u00a0\u00a0\u00a0 100",
  "seller": {"id": "2049", "name": "Umezawa", "city": "Москва", "refs": "1009"},
  "cost": 100,
  "eng_name": "Tarmogoyf",
  "name": "Tarmogoyf Nest",
  "rus_name": "Тармогойф"
}
```

Для внешних магазинов `seller` — строка, а `url` ведёт на сайт магазина:

```json
{"source": "MagicSpark.shop", "seller": "MagicSpark.shop", "city": "Москва",
 "url": "https://magicspark.shop/card/fra/116", "cost": 371, "qty": 1, "line": "…"}
```

### Состав источников (замер 2026-11-15, 15 карт → 1478 записей)

`topdeck` (треды продавцов на форуме), `MagicSpark.shop`, `MtgRussia.com`, `mymagic.ru`, `mtgsale`, `angrybottlegnome`, `autumnsmagic.com`, `mtglavka`, `time-cards.ru`, `bigmagic`.

То есть поиск — это **агрегатор цен по РФ**, а не только по своей площадке. Для «сколько стоит карта» лучшее, что есть публично.

### Семантика полей и подводные камни

* `cost` — цена за единицу из разобранной строки прайса. `qty` — количество в лоте. Бывают «лоты-пачки»: `qty: 4, cost: 46000` (продавец продаёт 4 RU-foil за 46 000). Для «минимальной цены» это даёт выбросы — фильтровать по медиане/перцентилю.
* `cost` иногда испорчен **на стороне TOPDeck**: их парсер берёт номер коллекционера за цену — `1 Enlightened Tutor #19 6ED en mp 1799` → `cost: 19`, `1 Otawara, Soaring City #271 NEO en Foil nm` → `cost: 271`. Отсекаем по совпадению `cost` с номером `#N`/`№N` из `line` (`prices.collector_misread`); на замере 2026-11-17 это портило минимум у 2–3 карт из 28.
* `stamp` — когда сайт последний раз переиндексировал прайс. Замер: **все записи имеют stamp одного часа ~04:30 МСК** → прайсы обновляются раз в сутки ночью. Внутридневного обновления цен от продавцов ждать нельзя.
* `name` — **карта из строки продавца**, то есть то, что реально продаётся; `eng_name`/`rus_name` — канонизированный запросный термин: при нечётком поиске (`Tarmogoyf`) там стоит запрошенное имя, а в `name` — `Tarmogoyf Nest` (пример выше); при RU-запросе (`Удар Молнии`) они дают английское имя карты. Поэтому офферы матчим к карте по `name`, а `eng_name`/`rus_name` годятся лишь как словарь RU↔EN от самого сайта (см. §9).
* `line` содержит HTML (`<b style='color:#777777'>`), это подсветка совпадения — при парсинге вырезать теги.
* Строки с `source: topdeck` содержат `seller.id` → ссылку на профиль `/apps/toptrade/member/<id>`.

### Лимиты поиска (важно!)

| Карт в запросе | Записей | Время ответа | Размер HTML |
|---|---|---|---|
| 1 (`Lightning Bolt`) | 184 | 1.6 с | 175 КБ |
| 5 | 339 | 4.2 с | 319 КБ |
| 8 | 1399 | 8.2 с | 1.21 МБ |
| 10 | **1478** | 9.4 с | 1.29 МБ |
| 12 / 15 / 20 / 40 | **1478** | 8–10 с | 1.29 МБ |

**Жёсткий потолок ≈ 1478 записей на ответ.** Всё, что не влезло, молча отбрасывается (карты из «хвоста» запроса не возвращаются вообще). Правило для бота: **не больше 5–8 карт на запрос**; если `len(records) >= 1478` — считать ответ усечённым и дозапрашивать карты по одной.

### Матчинг запроса

| Запрос | Результат |
|---|---|
| `Snapcaster Mage` | 21 запись, 1 карта |
| `snapcaster mage` | те же 21 (регистр не важен) |
| `Snapcaster` | 21 (подстрока работает) |
| `Uro, Titan of Nature's Wrath` | 16 |
| `Uro Titan of Nature's Wrath` (без запятой) | **0** — запятые и апострофы значимы |
| `Snapcaster Mage (ISD)` | **0** — скобки/сет ломают запрос |
| `1 Snapcaster Mage` | 21 — ведущее количество допускается |
| `Удар Молнии` (RU) | 184 → `eng_name = Lightning Bolt` — русский поиск работает |

Вывод: имена надо нормализовать (Scryfall → английское имя, без указания сета), а для русских названий сначала пробовать RU-запрос (он сам отдаёт `eng_name`).

## 4. Активные аукционы — все лоты одним запросом

```
GET https://topdeck.ru/apps/toptrade/auctions
```

Отдаёт **весь список активных лотов** (замер: 357 лотов) внутри `JSON.parse("…")`:

```json
{
  "id": "550142",
  "date_published": "1794773596",
  "date_estimated": "1795374796",
  "lot": "Bayou - Reserved List (Revised Edition, 3ED, REV, EN, №283)",
  "image": "4280f9.jpeg",
  "image_path": "2026/november",
  "start_bid": "500",
  "current_bid": "500",
  "bid_amount": "1",
  "bin_value": "0",
  "bin_value_original": "0",
  "shipping_info_quick": "Нахабино, почта",
  "shipping_info": "<p>…HTML…</p>",
  "date_published_conv": "15 ноября 2026",
  "date_estimated_conv": "22 ноября 2026",
  "time_left": "6д 22ч",
  "seller": {"id": "13397", "name": "pineapplepen", "city": "Нахабино", "refs": "7"}
}
```

### Семантика

* `date_published` / `date_estimated` — **Unix-epoch (UTC), абсолютное время начала и окончания**. Проверено сверкой с текстом страницы («до окончания 6д 22ч») и с системным временем. Это то, на чём строятся уведомления 1д/3ч/1ч/15м.
* `time_left`, `*_conv` — серверные человекочитаемые строки, для расчётов не годятся.
* `current_bid = "0"` при отсутствии ставок → показывать `start_bid`.
* `bin_value` — цена мгновенного выкупа (28 из 357 лотов), `bin_value_original` — до скидки.
* `shipping_info_quick` из формата «<Город>, почта» / «Только <Город>» — из него же клиентский JS выводит город и флаг «почта».
* Ссылка на лот: `https://topdeck.ru/apps/toptrade/auctions/<id>`.
* Превью: `https://topdeck.ru/apps/toptrade/uploads/<image_path>/thumb_<image>` (полный размер — без префикса `thumb_`).
* Продавец: `/apps/toptrade/member/<seller.id>`.

### Параметры и фильтры

`?page=2`, `?q=Bayou`, `?group=new`, `?sort=ending` — **игнорируются сервером** (отдаётся тот же массив из 357 лотов, побайтово равный). Все фильтры (`все/новые`, поиск по лоту/продавцу/городу, почта, выкуп, сортировка) считаются в браузере в `auctions/ActiveAuctionsVM`:
* «новые» = `now - date_published < 86400` (сутки);
* город = `shipping_info_quick` без `, почта` / `Только `;
* сортировки: `ending`, `bid`, `bin`.

**Следствие для бота:** один запрос на 54 КБ (gzip) каждые 14 минут закрывает все аукционы всех пользователей; матчинг с watchlist — локальный.

### Длительности и продление

Наблюдённые `date_estimated - date_published`: 23/24, 47/48, 72, 95/96, 118/120 ч и до 7.5 суток — продавец выбирает длительность. Признаков анти-снайп-продления на публичных страницах не найдено (в правилах и JS нет ни `продл`, ни `extend`), но **это надо подтвердить вручную** на живом лоте со ставкой в последние минуты: если `date_estimated` после ставки сдвигается — логика уведомлений должна перечитывать время, а не считать его фиксированным.

### Форматы/лимиты

* `Content-Encoding: gzip` поддерживается: 855 КБ → **54 КБ** (`Vary: Accept-Encoding`).
* Время генерации страницы ~0.75–1.3 с, кэша/CDN нет (никаких `Age`/`ETag`).
* 10 запросов подряд без паузы — все `200`, без rate-limit-заголовков. Тем не менее ставим троттлинг ≥1 с и свой User-Agent.

### Страница лота: состав лота (`composition`)

`GET /apps/toptrade/auctions/<id>` (~15–17 КБ) — единственный источник состава для мультикарточных лотов: в списке аукционов у них только общее название («Полноформатные Тропы KHM», «Полноформатные небазовые земли»).

Блок описания: `div.col-xs-12.tt-item-desc` → `h4 Описание` → абзацы `<p>` (проверено на 549985, 549976, 549223):

```html
<div class="col-xs-12 tt-item-desc">
  <h4>Описание</h4>
  <p>Состав лота:</p>
  <p><a class="topdeck_tooltipCard" href="/apps/cards/Blightstep%20Pathway">Blightstep Pathway</a>
     // <a class="topdeck_tooltipCard" href="/apps/cards/Searstep%20Pathway">Searstep Pathway</a> (KHM, #291, Showcase)</p>
  <p><a class="topdeck_tooltipCard" href="/apps/cards/Barkchannel%20Pathway">Barkchannel Pathway</a>  //  <a ...>Tidechannel Pathway</a>  (KHM, #290, Showcase)</p>
</div>
```

* Имя карты — текст ссылки `a.topdeck_tooltipCard` (в `href` то же имя, URL-encoded, включая кириллицу: `/apps/cards/%D0%A1%D0%B5%D0%B7%D0%BE%D0%BD%20%D1%83%D0%B4%D0%B2%D0%BE%D0%B5%D0%BD%D0%B8%D1%8F`).
* В одной строке может быть **две карты** через `//` (Pathways — лицевая/обратная сторона) — берём обе.
* Часть карт продавцы пишут **без ссылки**, просто текстом: `Bonder's Enclave (IKO,#363, Showcase)` — имя = текст до `(`.
* Служебные строки без карт («Состав лота:», «все на английском:») заканчиваются `:` — их отбрасываем.
* Остальное на странице (продавец, состояние, доставка, «Другие аукционы продавца») составом не является — парсим только `tt-item-desc`.

Для одиночных лотов та же страница бесполезна (название уже содержит карту), поэтому её скачиваем только когда название ни с чем не совпало или похоже на сборник, и **один раз на лот** (кэш `lots.composition_ts`).

## 5. История и статистика аукционов

### 5.1 Поиск по названию (включая завершённые)

```
GET /apps/toptrade/auctions/search?q=Snapcaster          → страница 1 (30 строк)
GET /apps/toptrade/auctions/search/<page>?q=Snapcaster   → страницы 2..N
```

Таблица: `Лот | Ставка | Продавец | Победитель | Завершен`, ссылки на `/auctions/<id>`, `/member/<id>`.
Пример строки: `Snapcaster Mage ENG (MM3, #050) | 1041 | 132 Modelist | 14 Николай Бысь | 5 ноября 2026`.

Минимальная длина запроса — 4 символа (подсказка в форме). Готовый источник «по сколько реально уходила карта».

### 5.2 Лента завершённых

```
GET /apps/toptrade/auctions/finished        → редирект/страница 1
GET /apps/toptrade/auctions/finished/<N>    → 50 строк/страница, пагинация до ~10 750
```

Таблица: `Лот | Ставка | Продавец | Победитель | Завершен`. Подходит для массового сбора истории (getprice использовал именно её), но 50 строк на запрос — для истории по конкретной карте лучше `auctions/search`.

## 7. IPS (движок): REST, GraphQL, RSS, форумы

### 7.1 REST/GraphQL закрыты ключом

```
GET  /api/                      → 401 {"errorCode":"2S290/6","errorMessage":"NO_API_KEY"}
GET  /api/graphql/              → 401 {"errors":[{"message":"INVALID_API_KEY","id":"3S290/7"}]}
POST /api/graphql/ {"query":…}  → 401 INVALID_API_KEY
GET  /api/system/hello, /api/forums/topics/<id>, /api/core/me  → 401, затем 429 TOO_MANY_REQUESTS_WITH_BAD_KEY
```

**Практический вывод:** API-ключ выдаёт только администрация; неавторизованные попытки быстро упираются в `429` по IP. Боту туда ходить не нужно (и вредно — можно получить бан по IP перед релизом).

### 7.2 Форумы (гостю доступны)

* `/forums/` — список разделов (198 КБ), `/forums/forum/144-продажа-карт/` — список тем, `?page=N` работает.
* `/forums/topic/<id>-<slug>/` — тема; текст постов в `div.cPost_contentWrap`. Именно здесь лежат прайс-листы продавцов, которые индексирует `singles/search` (поле `url` = ссылка на тему).
* `/search/?q=…&quick=1` — гостевой поиск IPS работает (возвращает страницу результатов).
* `?format=rss` и `/rss/*-feed.xml` — **404/игнорируются**: штатных RSS по форумам на этом инстансе нет.
* `/apps/mainrss` — единственная работающая лента: RSS 2.0, 30 записей, `title/link/pubDate/description` (дайджесты, анонсы). `?limit=` игнорируется.

## 8. Внутренние AJAX-эндпоинты (только со своей сессией + CSRF)

Найдены в `/apps/toptrade/toptrade.es6.js` (модуль `ToptradeAjaxHelper`, база `/apps/toptrade/`), все — `POST`, `dataType: json`, CSRF-пара в теле, ответ возвращает обновлённую CSRF-пару:

* `store/cart/update` — корзина (`id`, `action`: `add|inc|dec|del`, `val`);
* `member/<id>/store/reorder`, `moveorder`, `moveunorder`, `pullsale` — управление витриной продавца.

Публичных read-only AJAX-эндпоинтов нет: всё чтение — server-side rendering. Ставки на аукционах тоже идут обычной формой (`form.js-bid-form`, `validator.nextBid`, поле `bid`) с CSRF, т.е. автоматизация ставок = полноценный залогиненный клиент (в текущей задаче не нужна).

## 9. Полезные побочные находки

1. **RU↔EN словарь карт бесплатно.** `singles/search` возвращает пары `rus_name`/`eng_name` (`Удар Молнии` ↔ `Lightning Bolt`, `Тармогойф` ↔ `Tarmogoyf`). Можно накопить в БД и использовать для матчинга аукционных лотов на русском, где Scryfall не поможет (Scryfall отдаёт `printed_name` только для локализованных изданий).
2. **Названия лотов аукционов** имеют узнаваемый вид:
   `Bayou - Reserved List (Revised Edition, 3ED, REV, EN, №283)`,
   `4 Plains (Времена Года) BORDERLESS SURGE FOIL THE HOBBIT (317-320) ENG, NM`,
   `Foil Nissa, Leyline Tamer (Reality Fracture Commander, FRC №002)`.
   Отсюда извлекаются: количество префиксом, RU-имя до `-`, EN-имя после `-`, `(Сет, КОД, язык, №номер)`, флаги `Foil/Borderless/Extended Art/…`. Матчинг: нормализовать → Scryfall (`/cards/named?fuzzy=`) → при провале искать по RU-словарю.
3. **Картинки карт через сайт:** `/apps/cards/<Имя карты>` отдаёт `image/webp` (готовый прокси для веб-UI, но лучше брать Scryfall `image_uris`).
4. **Существующий конкурент:** в Telegram есть бот `@topdeck_auc_bot` («Topdeck Auctioneer», автор `@TheKid`, тема форума 541829) — уведомления по аукционам, живёт на VPS, периодически падает, сообщество собирает ему донаты. Подтверждает спрос; наш бот отличается веб-UI, персональными watchlist'ами и окнами 1д/3ч/1ч/15м.

## 10. Ограничения и правила приличия

* Потолок 1478 записей на поиск → батчи по 5–8 карт, проверка усечения.
* Ответы 1–10 с (поиск тяжелее с ростом числа записей); gzip обязателен.
* Нет ETag/Last-Modified/кэша → каждый опрос = полная выгрузка (54 КБ на аукционы).
* Rate-limit по публичным страницам не наблюдался, но он точно есть на `/api/` (429 после нескольких «плохих ключей»).
* `robots.txt`: `Disallow: /calendar/` для всех; боты Meta/Bing — целиком запрещены. Представляемся своим UA, держим интервал ≥1 с между запросами, не более ~100 запросов в час на раздел.
* Данные по завершённым лотам — персональные (ник победителя): хранить только публичные поля.
